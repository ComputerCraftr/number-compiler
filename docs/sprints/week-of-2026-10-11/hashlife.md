Period: 2026-10-11 through 2026-10-17 (Sunday–Saturday).

## Objective

Integrate source-authorized boundary and accumulator reuse from the downloaded
NC8 inputs while preserving the distinction between exact endpoint actions,
finite observations and unproved unrestricted future quotients.

## Changes

The current checkout starts at Git commit `9c2da16`. The archive APIs differ
from its existing scheduler and source-image owners. Selective adapters preserve
those owners. Decimal reverse boundary information is a separate requested CLI
observer. Collatz's requested accumulator shares the admitted root image and
retains exact affine endpoint/successor-sum actions in source-cylinder caches.

The follow-up adversarial audit replaced numeric-range construction cleanup
with context-local registration of exact owners and weak root references.
Rollback batches now retain their issuing store and exact leases, rejecting
foreign or stale batches before mutation. Region/concat leases are released
on failed view construction, sealing or dependency publication. Lease object
allocation and instrumentation failures are covered by publication rollback.

Mahler local actions now validate the requested cylinder and publisher before
reuse. Antihydra cylinder/projection keys reject Boolean and floating-point
aliases before lookup; rejected projection eviction leaves accounting intact.
Joint builders reject repeated entry and clean up failed entry. Joint cache
bypass counters distinguish capacity, disabled cache and query policy.
Decimal rendering no longer changes Python's process-wide integer digit limit.

The boundary-integration follow-up connects the CLI observer to the term's
existing source workspace and `SourceCarryPorts`. Original source decoding is
charged at admission; boundary extraction reads only its requested edge digits
and reuses carry-prefix summaries. Source request, ledger and disposal checks
apply before cached observation reuse. The explicit payload audit checks the
request seed against admitted digits. A shared incremental carry fold replaces
duplicated edge/nested forward and reflected boundary calculations.

The downloaded `finite_boundary_window.py` and its separate guarded-root cache
were not copied: they overlap the live ledger-owned implementation. Its
`full_q19_hashlife.py` retains explicit pair tuples and a restricted reset-region
language; it is not the live scheduler's missing temporal grammar successor.
The sources 1100022 and 1100522 now form an explicit regression: equal initial
windows and carry lead to different future high windows, 66 and 67. The relation
must preserve both possibilities. The same parameterized boundary engine covers
2*reverse arithmetic, but this does not supply a public 2rev10 endpoint family.

## Rejected approaches

The boundary-window relation does not determine unknown interior digits.
Its first carry is source-authenticated; future carries retain both branches.
The downloaded globally minimized Q19 region has an empty 24-step language
and does not admit seed-196 generation 17. Its finite paired-event Moore
minimality cannot establish an unrestricted temporal semigroup. Those cells
are not enabled as the default full-output constructor.

Collatz innovation/accumulator observers have explicit successor conflicts in
the downloaded audit. Exact joint action reuse must therefore remain keyed
by an authenticated source cylinder. Finite observation equality cannot
substitute another source's endpoint, width or chronological accumulator.

The ID audit found no theorem-backed additional merge for the exact time-action
or source-cylinder keys. The exact exponent in Collatz's action identity
distinguishes different functions, while source/fiber/endpoint data lives in
occurrences. Replacing either contract with a finite observer's Moore class
would lose information. The new joint cache is demanded by `--info accumulator`;
it does not establish a default-output construction speedup. The Isabelle
supplied-word results do not prove Python cache lifecycle or transport bounds.
