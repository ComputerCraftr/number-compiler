## Approved spatial boundary operands and current audit repairs

Result and interface keys now carry a fixed pair of optional canonical boundary
TileID views. These are exact spatial operands, not finite port states. Output
results carry the corresponding outgoing operands. Their leases, reverse
indexes, retirement and inventory are charged separately from finite-port
variants. The schema-6 representation policy is
`canonical-future-tiles-and-boundary-operands-v2`.

The primitive behavioral quotient now compares transition, output, all thirteen
fixed-cell channels, and occurrence observations (including Collatz odd-event
weights). Admission and emission use the quotient. Its fixed-cell signature is
not silently interchangeable with a composed whole-tile output quotient.
Refinement uses linear partition-equivalence checking. Runtime quotient records,
live residual classes, refinement work and observation work are separate metrics.

scoped validation. Independent audits still reject Boolean/float aliases,
foreign ownership, invalid sorts and stale IDs. C4 semantic compilation reuses
validated finite-function lifts within the index; it does not share warmed

These repairs do not establish arbitrary-depth demanded absorption or public
family cutover. In particular, accepting a boundary operand in a memo is not an
execution law for it. Unsupported execution remains explicit until every
transfer, observation and temporal dependency consumes the operand correctly.

## Active contract: canonical future tiles and complete results

This contract supersedes the historical prohibition on exact future tile nodes
in the checkpoints below. Immutable alphabet symbols and recursively interned
future tiles are permitted; flat intermediate words, packed histories, carry
slabs, normalized-tail buffers and trajectory lists remain forbidden.

One index owns one canonical tile arena, one retirement-aware execution memo,
and one iterative scheduler. A memo value is a `CompletedResult`: output tile,
outgoing interface and ports, physical/event/frame deltas, and relative
occurrence metadata. Tile identity contains only alphabet, level and canonical
content. Summaries are derived from that content. Neither execution provenance
nor accumulated caller weights belong to tile identity.

Completed hits bypass construction. Cold observations descend only demanded
branches with bounded sibling transfers; incomplete dependency frames remain
workspace. Completed midpoints are reusable but are never compulsory. Interface
compilation for a composite action must perform genuine bounded composition,
not conceal primitive replay behind a callback. Point/width applications hold
leases over completed roots or demanded subresults across observations.

## Release outcome

Every supported reverse/add, Collatz, and generic block-program point, width,
radix, and explicit-output path uses one executable binary temporal DAG over
spatial macrocells. Existing prime, Fermat, and Mersenne algorithms retain their
semantics and receive directory/API cleanup; this is not an algorithm rewrite
for those families. The existing exact
bimachine composition remains the mathematical definition. No production
adapter advances an orbit one generation or event at a time.

Original sources retain exact immutable geometry. Future high-level cells
retain source references, canonical programs, complete port actions, and
geometry. Exact future digits can exist only in the explicitly capped
microblock facility or explicit endpoint output. Slabs, packed carry histories,
coefficient tapes, and full Collatz intermediate tails do not enter action or
image arenas.

Success means completed correctness and resource gates on the routed engine,
including the fixed temporal and spatial measurements. Binary compiler size,
a large cache-hit count, or a capped attempt is not a passing execution result.
The existing composition establishes closure; the remaining problem is its
representation, normalization, reuse, and production execution.

## 2. Bounded digit materialization contract

Introduce an index-owned `MicroblockCache` separate from every semantic arena.
It is an optimization of the same evaluator, not another orbit backend.

Proposed initial settings, frozen before benchmark comparison:

- At most 64 encoded digit bits per block, with an aligned dyadic symbol count
  selected from the kernel alphabet. No single arithmetic limb exceeds 64 bits.
- At most 1,024 retained blocks and 8 KiB of encoded digit payload per index.
  Both caps apply, as do the ledger's ordinary entry/node limits. Metadata and
  Python object storage are inventoried separately rather than called 8 KiB.
- At most 256 bytes of simultaneously live transient microblock payload across
  the scheduler, including uncached results, decoding, and in-flight fills.
  Stack frames hold handles and cursors, not one digit buffer per stage.
- Capacity zero disables this optimization. Exhaustion evicts eligible blocks
  or evaluates without retaining them; it cannot expand either cap. A ledger
  with zero required program capacity still fails before program allocation.
- A symbol that cannot fit the microblock encoding uses the symbolic/scalar
  path. This does not introduce a new user-visible radix restriction.

The tuning values are proposed implementation defaults, not measured results.
Any change to them must be recorded before the comparison run; limits cannot
be increased to make a failed release sample pass.

Keys use validated canonical source/image, temporal-program, frame, aligned
local block geometry, and observation-port IDs. They contain no absolute
generation/position occurrence identity. A concrete port belongs to the
observation key, never to a new semantic image-cell identity.

Every radix/view shares one budget and one canonical underlying binary-block
provider for Collatz. If division intermediates need microblock reuse, they
must use that same accounted facility with their canonical division-program
IDs. They cannot create a per-radix parallel exact cache. Binary microblock
reuse alone is insufficient if deep division stages still replay exponentially.

Reserve payload and container capacity before emitting a retained block. The
cache alone owns its payload; semantic nodes, callbacks, suspended tasks, or
external bound views must not pin evicted payloads. Borrowed blocks are counted
as live until released. Charge the full backing allocation, not the length of
an exposed slice: an eight-byte view cannot pin an uncharged larger buffer.
Count each backing allocation once, with separate records for aliases, leases,
and pending ownership; include derived-radix re-encodings under the same cap.
Microblock IDs are monotonic live-entry identities, not recycled slot numbers.
A lookup of an evicted/refilled ID fails before a warm shortcut. No growing
payload or tombstone arena is needed to preserve stale-handle rejection.
Failure or cancellation releases all pending charges.

No `DyadicTile`/`DyadicSpan` future-tree construction is permitted by this
facility. High-level joins compose actions and references; they never join
exact microblock values into an uncapped future tape. The source-only tree
guard remains active. The new authority authorizes a bounded buffer allocation
only, not endpoint lowering or arbitrary exact-tree constructors.

The previous “zero future digit payloads” test becomes two separate assertions:
zero forbidden future representations, and an independently verified cap on
permitted exact microblock storage. Small outputs may fit entirely in the
approved cache; this is an explicit consequence of the new allowance. Wide
outputs cannot accumulate beyond its fixed total capacity. H-row histories,
full coefficient offsets, and full affine B values remain forbidden regardless
of whether an individual field happens to be small.

## 3. Shared arenas, normalized identities, and higher macrocell reuse

Freeze these interfaces before family agents change routing:

| Owner | Contents and responsibility |
|---|---|
| `ExecutionContext` | Ledger created before compilation; all mutable stores and capabilities for one index/term |
| `SourceCellArena` | Exact original cells and blank padding; weak immutable sharing, non-recycled identities |
| `TemporalActionArena` | Immutable kernel references and normalized binary compositions |
| `BoundaryActionArena` | Reduced finite functions and complete structured continuation programs |
| `ImageCellArena` | Parametric future references with level, orientation, phase, and source association |
| `MicroblockCache` | Strictly capped, evictable exact digit observations; no semantic-node ownership |
| `MaterializedEndpointArena` | Explicit caller-requested output under a separate capability |

All public handles validate exact owner, kind, local integer ID, lifetime, and
expected sort before warm lookup or identity reductions. IDs are monotonic and
are not recycled after eviction. Private validated array offsets stay integers.
Neither `id(object)` nor a kernel name serves as semantic identity.

Kernel definitions freeze transition/output/alphabet/blank/initial-state data,
including callables whose mutable closures would otherwise change behavior.
Use a versioned deterministic digest plus exact frozen-definition equality
before sharing. Family certificates bind semantic identity, radix, exponent,
and source encoding; they select valid optimizations, never a different loop
backend. Unsupported custom atoms fail explicitly without eager fallback.

Preserve the existing `U` and `K` equations in `diamond_higher_context.py`:
composed unary transfer transports both anchor and continuation; spatial
context composition uses both provider midpoint ports. Extend their carrier
to reduced function DAGs whose terminals can reference canonical structured
continuations, not merely integer-valued primitive states.

Use typed open ports and fixed semantic ordering (time, side, role, bit),
canonical bound-variable numbering, identical-branch elimination, invalid-port
normalization, and certified reset/constant reductions. Preserve child sharing
through substitution. Do not enumerate a growing Cartesian product of H-stage
states. Do not replace a free outer port by an occurrence-specific scalar to
make an inner continuation reducible.

Distinguish `ActionProgramID` (normalized syntax), `BoundaryActionID` (a
certified finite function on its declared port), and `CompleteMacroActionID`
(a typed record containing the complete semantic components). The complete
record includes boundary transfer, coordinate-parametric output substitution,
activity, extent, both directions, halos, growth and termination. Each component
retains its own sort and equivalence guarantees. Carry exits alone cannot
certify equality of complete macro actions. Source provenance belongs to the
image/application binding, outside the semantic action interner.

An immutable `PortSignatureID` binds the kernel identity, channel definitions,
admissibility rules, and composition interfaces. Where a bounded H theorem is
used, its port dimension is independent of spatial width. Higher composed
interfaces remain shared symbolic DAGs, not dense state products or numeric
pieces of a future field.

The existing API is `compose(before, after)`, meaning apply `before` and then
`after`. Normalize `Image(B, Image(A, C))` to
`Image(compose(before=A, after=B), C)` before lookup. A noncommuting-kernel
regression verifies this order; powers of one kernel would hide a reversal.
Transport frame and interface wiring into the composition. Repeated incoming
port observations cannot allocate more image macrocells. Mirror exchanges
directions and halos; conjugacy is used only where the complete kernel law is
verified. Neither implies that nonlinear evolution is invertible or that an
arbitrary action commutes with reflection.

One iterative scheduler probes the largest relevant canonical parent/diamond
before requesting children. Parent publication, associated interner entries,
and memo entries reserve atomically. Distinguish early request hits from late
reductions that discover a known result. No flattened primitive itinerary,
generation loop, persistent nested-image chain, or stage-sized carry array is
allowed. Bounded microblocks are the leaf cutoff of this scheduler.

## 4. Implementation sequence and exit gates

### A. Stabilize the audit repairs and freeze the contract

Keep the already patched ID, symmetry, input, source-authority, and inventory
regressions. Inventory every mutable store and current public execution route,
including direct block APIs, radix conversion, zero/identity cases, and explicit
output. Record an import/export manifest before any module move.

Extend the ledger with atomic microblock payload reservations, eviction,
borrowing, cancellation, and disposal accounting. Add negative controls that
inject an unregistered buffer, spoof a role, omit a callback, and retain an
evicted payload through a closure. Audit actual reachable objects and buffers,
not just counters asserted by the cache itself.

Exit: scoped interfaces frozen; the new exact-data allowance has executable
cap/ownership tests; no audit repair is silently reverted.

### B. Recover radix speed with bounded shared blocks

Implement the shared microblock provider and use it from scalar/radix queries
through the same canonical source/program identity. Replace one-bit replay with
bounded block consumption. Compile repeated division stages as shared programs
and compose their finite range effects; use the same bounded cache for any
permitted derived microblocks. Keep arbitrary future prefix observations
transient and avoid numeric offset/residue collections outside this cache.

Exit: reproduce and fix the radix-3 digit-3 regression with source
`(1 << 95) + 0x123456789ABCDEF12345` after one physical Collatz step, at the
original 5,000-node and 10,000-entry limits. Before implementation, freeze a
same-machine, fresh-process benchmark with no concurrent CPU-heavy jobs. The
initial gate is median cold digit-3 time at most 0.25 seconds and repeat time
at most 0.01 seconds over five independent trials, with exact answers and all
storage caps enforced. Record CPU time and actual work as well as wall time;
retain the observed earlier approximately 0.198-second cold result. This
separate speed gate cannot be replaced by the 35-second matrix watchdog.

The existing long nonbinary point and q64 tests must also complete at their
unchanged gates. Exercise radix 3, 6, 12,
multiple concurrent radix views, and churn past the byte and entry caps. Poison
whole `.digits()`, `.materialize()`, and exact-tree constructors during point
queries. Cold, repeat, evicted, and cache-disabled answers agree.

This phase may repair the current adapter's leaf provider to restore the test
baseline, but introduces no new successor loop and is not called the cutover.
The same provider must be reusable unchanged by the shared diamond executor.

### C. Complete structured continuation reduction and parent reuse

Implement higher function-valued normalization and substitution over the
existing U/K composition, preserving free-port scope and typed interfaces.

replace its exact-output-tile identity with action/program identity.

Start with the saved nested-continuation and repeated-parent witnesses. Extend

work whenever the equivalence follows from admitted laws.

Exit: warm parent transfers answer with child/leaf evaluators poisoned and
both microblock/last-response caches disabled. Multiple boundary observations
reuse the same parent. A large parent owns one coordinate-parametric output
program, not one specialized function per coordinate. Exhaustive small-domain

### D. Integrate both families and all generic entry points

Reverse/add uses the existing `DiamondReverseApplication` semantics and the
verified T² optimization. Generation zero reads original digits; positive

terminal normalization. Bases 2–5 keep their exact admitted kernels; base 2

Growth remains a conditional action until the requested observation needs it.
